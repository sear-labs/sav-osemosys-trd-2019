# Reproduction notes

What was measured, by what, and what the measurement does not cover. Kept here rather
than in `CLAUDE.md`, which states conventions; this states results. A number here is a
measurement with the run that produced it, so a reader can tell one that was measured
from one that was chosen to make a check pass.

Measured 2026-09-24 unless stated: Python 3.13.9, matplotlib 3.10.6, Windows 11,
GAMS 42.5 / CPLEX for the GAMS path, gurobipy 13.0.2 and HiGHS for the Python path.
`pytest` is 50 tests, about a second. The scenario solves are not in it — see

## 1. The machine-path leak, and what it cost

`notebooks/01_model.ipynb` committed an absolute path in cell output:
`build_model_notebook.py` printed `Instance.source`, which returns the resolved local
instance directory. The executed notebook was committed with it, so the repository
published a home directory and a username.

Fixed at the print statement (PR #1), not normalised in a comparison. A normaliser for
a value this repository chose to print keeps hiding it from every reader who is not
diffing bytes. The notebook now prints `local clone` or `GitHub (no local clone found)`,
which carries the information a reader needs and nothing else.

**The `v1.0.0` tag still contains it. The Zenodo deposit does not.** Zenodo was connected
to this repository three days after `v1.0.0` was released, and its webhook fires only on
*new* releases — so no deposit was ever created from that tag. Confirmed against the
record rather than inferred: `zenodo.org/api/records/22715621/versions` returns exactly
one version.

| | |
|---|---|
| Concept DOI (always latest) | `10.5281/zenodo.22715620` |
| Version DOI (the only deposit) | `10.5281/zenodo.22715621`, `v1.0.1`, published 2026-09-12 |

## 2. Why nothing here caught it

Nothing swept the committed files. `scripts/check_no_machine_paths.py` now does, and
`tests/test_no_machine_paths.py` runs it. Three details in that sweep each report
success while failing, and each was found the hard way:

- **Enumerate with `git ls-files -z`.** A whitespace split fragments any path containing
  a space into pieces that do not exist, skips them, and still prints a plausible file
  count. This repository has no such path today, so the sweep demonstrates the bug on a
  synthetic one rather than proving nothing. `houston-covid-gis` has fourteen.
- **Assert every listed path resolves.** "Skipped silently" is the failure mode; a
  "scanned N files" line cannot distinguish it from a scan.
- **Probe the pattern before trusting its silence.** A regex for one-or-two literal
  backslashes matches nothing if one character is wrong, and reports success.

The guard existed from PR #1 but **nothing ran it until PR #3** — it fired only when
somebody remembered, which is the condition it exists to remove.

Current: 169 tracked files swept, 0 machine paths, no credentials at any tag.

## 3. Embedded figures are compared by presence, not by bytes

`scripts/check_notebooks.py` re-executes both notebooks and compares every output
channel against what is committed — except `image/png`, which is compared only for
presence. That is a limit, not an oversight, and two separate mechanisms force it:

**matplotlib stamps its own version into the PNG.** Read from a committed output:

    tEXt  Software\0Matplotlib version3.10.6, https://matplotlib.org/
    IHDR  978x483

So any version difference changes the bytes, for a reason unrelated to the result.

**`bbox_inches="tight"` crops to the rendered extent of text**, which depends on font
metrics that differ by platform. `scripts/make_figures.py:58` passes it explicitly; the
notebooks never call `savefig` at all, but ipykernel's inline backend defaults every
`plt.show()` to the same behaviour. A peer session measured this on real CI — the same
figure returned a different **pixel shape**, 1388×586 against 1389×587 and 976×643
against 979×644 — so there is nothing to compare element-wise even in principle.

Comparing exactly would make the check pass only on the machine that generated the
committed notebooks, which is the same failure the leak in section 1 was. Presence still
catches a figure that stopped rendering; it does not catch one that rendered differently.

**Not covered anywhere:** committed figures are never compared byte-for-byte on the
machine that maintains them, which is the only machine where that comparison means
anything. Measured once by hand — all five PNGs regenerated byte-identical — but nothing
enforces it.

## 4. Both notebooks reproduce, and the last gap was a stopwatch

After section 1 and section 3, re-execution matches committed output exactly:

| Notebook | Code cells | Strict match |
|---|---:|---|
| `00_verify.ipynb` | 9 | 9 |
| `01_model.ipynb` | 13 | 13 |

`01_model.ipynb` was 12 of 13 until the solve-time print was removed. The entire
difference was `solve time 0.5s` against `0.4s`, with the objective identical at
`5,900.422796`. A wall-clock reading has no bearing on any result and was the only thing
between this repository and byte-exact notebook reproduction. Removed at the source
rather than normalised, for the same reason as section 1.

HiGHS solving the reduced instance is deterministic here: same objective, same bytes.

## 5. A test that could not tell two claims apart

`test_building_a_model_still_needs_a_solver` wrapped both statements in one
`pytest.raises`: importing `sav_osemosys.model`, and calling `build()`. Verified by
injection that this **passes silently** if `model.py` ever starts importing gurobipy at
module level — the exact defect the file exists to catch — because `ImportError` simply
arrives one line earlier.

Split in PR #1. The split version fails and names which claim broke.

## 6. Fifteen of sixteen alias entries never execute

`data.py`'s `_ALIASES` maps GAMS alias columns to canonical set names. Instrumented the
resolver and loaded every symbol across all ten scenarios: **only `r` ever fires**, on
`DemandResponseDiscountRate`. The other fifteen entries and the `.lower()` / `.upper()` /
`Dim1` fallbacks never run.

Not a bug, and left in place: a miss raises `KeyError`, and the only caller
(`Parameters._load_base`) catches `FileNotFoundError` and `ConnectionError` but not
`KeyError`, so an unresolvable column propagates loudly. Confirmed by reading the caller,
not just the raiser. Removing the fifteen leaves all tests green; removing `r` turns
several red — so the mechanism is covered, at exactly one entry of sixteen.

## 7. What a cloner cannot check

`results/clean/` regenerates byte-identical from `scripts/clean_output.py` — verified by
hashing before and after. But the raw GAMS output it derives from lives under
`results/scenario-NN/`, which is gitignored. **So that verification does not travel:** it
was done here and cannot be repeated by anyone who clones.

Stated rather than implied, because a verification only the author can run is weaker than
one that ships, and the gap is invisible unless it is written down.

Likewise: every licence-free claim in this repository is tested by *blocking* the solver
import, which is a faithful simulation of not having a licence and is not the same fact.
Nothing here has run on a machine that genuinely lacks one.

## 8. Audit of the sibling DOI'd repositories

Six repositories carry Zenodo DOIs. Swept every tagged tree of all six for machine paths
and for credential-shaped secrets. **No credentials anywhere, at any tag, including HEAD.**

Two deposits carry machine paths — `lithium-optsc-energies-2024` and
`water-energy-coopt-scs-2021`. Jones's decision on 2026-09-14 was **no re-release**: these
are public works, nothing in the paths is private, and the deposits are immutable anyway.
The git trees were cleaned and guards added instead, so nothing future carries them.

The full per-repository picture is in `claude-notes`,
`notes/2026-09-24-zenodo-doi-audit.md`, not here — it concerns six repositories and would
go stale in any one of them.

One finding from that audit belongs here because it is about how checks mislead:
`lithium` already had a test called `test_no_absolute_paths_in_source`. It opens **one
file**, `src/lithium_energies/model.py`. Its name reads as a statement about the source
tree; it is a statement about one module. The leak was in a notebook it never opens, so it
passed throughout — and the release it passed on is the one Zenodo archived. A check that
sounds tree-wide and is not is worse than no check, because its passing is read as
coverage it never had.
